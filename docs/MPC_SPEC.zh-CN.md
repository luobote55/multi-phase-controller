# MPC Skills 规范说明

## 目的

本文档定义以下 5 个 skills 的行为契约：

- `mpc-master-start`
- `mpc-master-progress`
- `mpc-master-regress`
- `mpc-master-archive`
- `mpc-slave`

这套 skills 的定位，是服务于 GSD 项目的多 phase 管理辅助记录工具。核心目标是把 GSD 已拆分的任务列表整理写入 `<repo-root>/.mpc/mpc.md`，并在多对话协作过程中维护共享进度真相。它是 GSD 的补充，而不是替代 GSD 的主工作流。

`mpc-master-regress` 和 `mpc-master-archive` 仍然保留，但它们属于可选治理能力，不再是本规范的唯一主轴。

## 管理文件

- 活动控制文件：`<repo-root>/.mpc/mpc.md`
- 归档控制文件：`<repo-root>/.mpc/mpc_archive.md`
- 锁文件：`<repo-root>/.mpc/.lock.md`

约束如下：

- 这些文件位于当前项目仓库根目录的 `.mpc/` 中，同一仓库的所有会话共享同一份控制文件。
- 文件名固定为 `mpc.md`、`mpc_archive.md` 和 `.lock.md`。
- `.lock.md` 是临时写锁，只读 skill 不创建它。
- 如果文件尚不存在，由 `mpc-master-start` 或首次归档动作创建最小骨架。
- 始终先解析当前项目的 Git 仓库根目录，再使用该根目录下的 `.mpc/`。

## 核心原则

- `mpc.md` 的首要价值是承接 GSD 已拆分任务，并维护多会话协作中的共享进度真相。
- 主控侧 skills 负责整理导入、只读查看、可选回归、可选归档，不代替子任务做日常开发。
- 子任务通过显式 `任务标识` 驱动，不依赖目录或分支自动识别。
- 单目录模式是主流程：多个子任务在同一仓库目录中，通过多开对话并行推进。
- 默认约束是“同一时刻一个任务只由一个对话推进”；本规范不额外提供会话认领机制。
- 当源文档已经是 GSD 已拆分任务列表时，优先保留其顺序、粒度和语义，只做规范化录入。
- 如果存在明显依赖或冲突，必须显式写明 `前序子任务` 和 `后序子任务`。
- 只要涉及同文件、同核心模块、路由或注册表、依赖清单、生成产物、共享导出面，或存在明显顺序关系，就必须拆成串行任务，而不是并行任务。
- `mpc.md` 必须保持固定字段顺序，字段不可省略；空值必须写成 `待填写` 或 `无`。
- 查看类动作必须保持只读，状态推进必须显式触发。
- 所有时间统一使用 `YYYY-MM-DD HH:mm:ss +08:00`。
- 除 `mpc-master-progress` 外，所有写入动作都必须持有 `<repo-root>/.mpc/.lock.md`。

## 子任务状态机

每个子任务只允许使用以下 4 种状态：

- `未开始`
- `进行中`
- `完成`
- `已回归`

唯一允许的正常流转路径为：

`未开始 -> 进行中 -> 完成 -> 已回归`

职责分工如下：

- `mpc-master-start`：创建新任务，初始状态为 `未开始`
- `mpc-slave`：负责 `未开始 -> 进行中` 与 `进行中 -> 完成`
- `mpc-master-progress`：只读查看
- `mpc-master-regress`：负责可选的 `完成 -> 已回归`
- `mpc-master-archive`：负责可选的已回归任务归档

归档不是状态，而是只允许发生在回归通过之后的动作。

## `mpc.md` 固定结构

`mpc.md` 中每个任务块都必须保持以下字段顺序：

`任务标识 -> 状态 -> 来源计划文件 -> 执行模式 -> 执行目录 -> 前序子任务 -> 后序子任务 -> 子任务目标 -> 开始时间 -> 完成时间 -> 回归时间 -> 归档时间 -> 最后更新时间 -> 累计耗时 -> 预计剩余时间 -> 当前进度概况 -> 阻塞事项 -> 下一步提示词 -> 开始提示词 -> 完成提示词 -> 完成摘要 -> 回归摘要 -> 归档状态`

补充要求：

- `执行模式` 当前固定为 `single_dir`。
- `执行目录` 当前固定为 `.`。
- `当前进度概况` 最多 5 行。
- `阻塞事项` 最多 5 行；没有阻塞时写 `无`。
- `累计耗时` 与 `预计剩余时间` 使用 `Xd Xh Xm` 形式，例如 `4h 30m`。
- `完成摘要` 至少覆盖：完成内容、涉及文件或模块、自检命令与结果、剩余风险、建议主控回归关注点。
- `回归摘要` 至少覆盖：回归范围、证据、回归结果、是否允许归档。
- `归档状态` 只能是 `未归档` 或 `已归档`。

## 提示词模板约束

所有由 MPC skills 生成或展示给执行者的任务提示词，都必须显式带上 GSD 能力语义。

- `开始提示词` 首句必须以 `利用gsd skills的能力，实现需求：<当前子任务目标摘要>` 开头。
- `下一步提示词` 在自动生成或刷新后，也必须保留同样的开头，而不是删除或改写这层语义。
- `完成提示词` 必须明确说明结论是基于利用 GSD skills 推进该任务后的产出进行确认。
- 旧的硬编码阶段命令示例不再允许继续使用，必须统一改成可复用的 GSD 协作提示词模板。

推荐模板如下：

```text
利用gsd skills的能力，实现需求：<需求摘要>。先确认边界与现状，再推进实现，并在过程中持续同步可用于更新 mpc.md 的进展信息。
```

```text
利用gsd skills的能力，实现需求：<需求摘要>。结合当前已完成内容、剩余工作与阻塞项继续推进下一步，并准备同步最新进度。
```

```text
基于利用gsd skills推进该任务后的产出，请确认是否已经满足需求：<需求摘要>；请给出完成依据、风险与是否可进入下一阶段的结论。
```

## `mpc_archive.md`

- 归档文件中的单个任务结构与 `mpc.md` 完全一致。
- `任务总数` 表示当前文件中的任务块数量。
- 归档是移动，不是复制。
- 归档后必须满足：
  - 任务从 `<repo-root>/.mpc/mpc.md` 删除
  - 任务追加到 `<repo-root>/.mpc/mpc_archive.md`
  - `状态` 仍为 `已回归`
  - `归档状态` 变为 `已归档`
  - `归档时间` 已填写
- 查询和依赖检查必须覆盖 `<repo-root>/.mpc/mpc.md` 与 `<repo-root>/.mpc/mpc_archive.md` 的并集，优先查询活动文件。
- 如果同名任务同时存在于两个文件中，视为严重数据异常。

## 并发写入规则

虽然真实冲突概率通常不高，但所有写入仍必须串行化。

1. 除 `mpc-master-progress` 外，所有写入动作都必须先申请 `<repo-root>/.mpc/.lock.md`。
2. 锁文件至少记录：
   - 持有者 skill 名称
   - 目标任务或任务列表
   - 当前仓库目录或分支
   - 加锁时间
3. 如果锁已存在，每 2 秒重试一次，最多等待 60 秒。
4. 如果锁持续超过 10 分钟未释放，视为陈旧锁，必须停止并明确报错。
5. 获取锁后必须重新读取最新 `<repo-root>/.mpc/mpc.md`；必要时也读取 `<repo-root>/.mpc/mpc_archive.md`。
6. 除 `mpc-master-start` 外，每次写事务只允许修改一个任务块和文件头部元信息。
7. `mpc-master-start` 可以在一次事务中追加多个任务块，并以最小改动范围更新直接前序任务的 `后序子任务`。
8. 不得重写无关任务内容、顺序或提示词。
9. 写入必须使用“临时文件 + 原子替换”。
10. 每次成功写入后，都要更新：
    - 文件级 `最后更新时间`
    - 文件级 `任务总数`
    - 任务级 `最后更新时间`
11. 如果待写内容基于旧快照，必须先基于最新内容重建，不能直接覆盖。
12. 只要持有过锁，无论成功还是失败，退出前都必须释放锁。

## 任务整理与轻量拆分规则

`mpc-master-start` 在整理任务时必须满足：

- 输入仍然是一个需求或计划文件路径。
- 默认把该文件视为 GSD 已拆分任务列表的来源。
- 如果源文档已经是可执行任务清单，优先保留其顺序、粒度和语义，只做规范化录入。
- 只有在条目明显过粗、混合多个可分离工作、或无法形成可跟踪进度的任务时，才做轻量拆分。
- 任务名全局唯一。
- 不得与 `mpc`、`mpc_archive`、`lock` 等保留名称冲突。
- 任务名只能使用小写字母、数字和下划线。
- 如果需要补做轻量拆分，默认把一个需求整理为 3 到 10 个可执行步骤。
- 如果任务之间存在明显冲突或强依赖，必须拆成串行子任务，而不是并行任务。
- 只要命中以下任一场景，也应按串行任务建模：同文件、同核心模块、路由或注册表、依赖清单、生成产物、共享导出面。
- 如果是在现有链路后续追加任务，只允许最小范围更新直接前序任务的 `后序子任务`。
- 不新增“路径归属检查”或“会话认领机制”；冲突控制主要依赖任务切分、前后序和调用纪律。

## 任务树与新增任务清单输出

`mpc-master-start`、`mpc-master-progress`、`mpc-master-regress`、`mpc-master-archive` 在命令结束时，都必须输出一次最新任务树。

任务树规则如下：

- 任务树基于 `<repo-root>/.mpc/mpc.md` 与 `<repo-root>/.mpc/mpc_archive.md` 的并集生成；如果归档文件不存在，可以忽略。
- `前序子任务` 与 `后序子任务` 在存在多个任务时，统一按 `、` 拆分；`前序子任务 = 无` 的任务视为根节点。
- 子节点顺序严格使用父任务 `后序子任务` 中的顺序；根节点顺序优先保持 `mpc.md` 中的原始顺序。
- 树状图字符统一使用 `├─`、`└─`、`│  ` 与 3 个空格缩进。
- `mpc-master-progress`、`mpc-master-regress`、`mpc-master-archive` 默认应在节点后追加状态标签；已归档任务统一显示为 `[已归档]`。
- 如果发现同名任务同时存在于活动区与归档区、循环依赖、缺失子任务、或同一子任务被多个父任务直接声明为后序任务，必须立即报数据异常并停止。

其中，`mpc-master-start` 的输出顺序固定为：

1. `本次新增任务清单`
2. `最新任务树`
3. `首轮可执行任务与 /mpc-slave 命令`

`本次新增任务清单` 必须覆盖本轮全部新增任务，并按写入顺序列出至少以下字段：

- `任务标识`
- 1 行 `子任务目标` 摘要
- `前序子任务`
- `状态`

不能只列首轮任务；被阻塞任务也必须出现在这份清单里。

## 各个 skill 的定义

### `mpc-master-start`

手动调用示例：

```text
/mpc-master-start docs/example_plan.md
```

职责：

- 读取 GSD 计划文档或已经拆分好的任务列表。
- 判断哪些条目可以直接录入，哪些条目只需要轻量整理，哪些条目必须补做轻量拆分。
- 在 `<repo-root>/.mpc/mpc.md` 中创建新的任务块。
- 自动生成：
  - `任务标识`
  - `前序和后序关系`
  - `子任务目标`
  - `开始提示词`
  - `完成提示词`
- 所有新任务固定写入：
  - `执行模式 = single_dir`
  - `执行目录 = .`
- 必要时创建 `<repo-root>/.mpc/` 和最小 `mpc.md` 骨架。
- 输出首轮可执行任务的建议启动命令，但绝不自动执行。

额外要求：

- 生成的 `开始提示词` 必须以 `利用gsd skills的能力，实现需求：...` 开头。
- 为下游 `mpc-slave` 刷新 `下一步提示词` 保留同样的前缀规则。
- 输出时必须先罗列本次全部新增任务，不能只展示首轮任务。

### `mpc-master-progress`

手动调用示例：

```text
/mpc-master-progress
/mpc-master-progress phone_1_requirement_1
```

职责：

- 保持只读。
- 展示全部活动任务概览，或展示单个任务详情。
- 优先查询 `<repo-root>/.mpc/mpc.md`，未命中时再查 `<repo-root>/.mpc/mpc_archive.md`。
- 在展示 `开始提示词`、`下一步提示词`、`完成提示词` 时，保持原文，不要移除 GSD 能力前缀。

### `mpc-master-regress`

手动调用示例：

```text
/mpc-master-regress phone_1_requirement_1
```

职责：

- 只处理一个当前状态为 `完成` 的任务。
- 这是可选的主控回归确认能力，不是任务记录主流程的唯一重点。
- 回归证据优先来自：
  - `完成摘要`
  - 自检命令与结果
  - 当前总代码状态
  - `子任务目标`
- 审核对象应理解为“基于利用 GSD skills 推进后的任务产出”。
- 先给出建议，再等待明确确认。
- 只有得到明确确认后，才把任务推进到 `已回归`。

### `mpc-master-archive`

手动调用示例：

```text
/mpc-master-archive phone_1_requirement_1
```

职责：

- 只处理一个当前状态为 `已回归` 的任务。
- 这是可选的历史归档能力。
- 把该任务从 `<repo-root>/.mpc/mpc.md` 移动到 `<repo-root>/.mpc/mpc_archive.md`。
- 必要时创建最小归档文件。

### `mpc-slave`

手动调用示例：

```text
/mpc-slave phone_1_requirement_1
```

职责：

- 必须接收一个显式 `任务标识` 参数。
- 禁止从当前目录名、git 分支名或最近改动中自动猜测任务。
- 使用 `<repo-root>/.mpc/mpc.md` 作为控制文件。
- 负责推进已记录任务的执行状态与进度同步。

按状态行为：

- `未开始`
  - 检查所有前序任务，查询范围覆盖活动区和归档区
  - 只有全部前序任务都为 `已回归` 时才允许启动
  - 初始化开始时间、预计剩余时间，并令 `下一步提示词 = 开始提示词`
- `进行中`
  - 更新进度概况、阻塞事项、预计剩余时间、下一步提示词、最后更新时间
  - 优先读取当前仓库目录 `./planning/` 下最新且最相关的文件
  - 自动生成或刷新 `下一步提示词` 时，必须保留 `利用gsd skills的能力，实现需求：...` 这一前缀
  - 如果证据足够，先提出“建议已完成”
  - 证据展示必须至少包含：已完成内容、涉及文件或模块、自检命令与结果、尚存风险、建议主控回归关注点
  - 只有得到明确确认后，才推进到 `完成`
- `完成`
  - 只展示完成信息
  - 不能直接推进到 `已回归`
- `已回归`
  - 只展示回归和归档信息
  - 提示调用者改用 `mpc-master-archive`

## 最小闭环要求

以下能力都成立时，这套设计才算真正可用：

1. `mpc-master-start` 能稳定整理导入 GSD 任务列表，并创建结构正确的子任务。
2. `mpc-master-progress` 能稳定提供只读总览与任务树。
3. `mpc-slave` 能根据显式 `任务标识` 准确命中自己的任务，并在确认后推进到 `完成`。
4. `mpc-master-regress` 能在需要时基于完成摘要、自检结果和当前总代码状态给出回归结论，并在确认后推进到 `已回归`。
5. `mpc-master-archive` 能在需要时安全归档一个已回归任务。
6. 多个对话并行工作时，不会因为覆盖写导致状态丢失。

## 明确禁止的行为

- 不得把“查看状态”设计成“顺便改状态”。
- 不得让 `mpc-slave` 绕过前序依赖。
- 不得让 `mpc-slave` 从 `进行中` 直接跳到 `已回归`。
- 不得让 `mpc-master-progress` 承担回归或归档动作。
- 不得归档尚未完成回归的任务。
- 不得在未持有 `<repo-root>/.mpc/.lock.md` 时写控制文件。
- 不得只查 `<repo-root>/.mpc/mpc.md` 就判断前序任务不存在。
- 不得在更新一个任务时重写无关任务块。
- 不得省略固定字段，导致下游解析失败。
- 不得让 `mpc-slave` 无参数运行或自动猜测任务名。
