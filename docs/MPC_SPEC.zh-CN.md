# MPC Skills 规范说明

## 目的

本文档定义以下 5 个 skills 的行为契约：

- `mpc-master-start`
- `mpc-master-progress`
- `mpc-master-regress`
- `mpc-master-archive`
- `mpc-slave`

这套 skills 是对常规 GSD 工作流的一层小型补充，用 `~/.mpc/{工程项目名}/mpc.md` 和 `~/.mpc/{工程项目名}/mpc_archive.md` 作为控制中心，让一个主控会话和多个在同一仓库目录中并行推进的子任务对话可以协作推进任务，同时尽量避免状态丢失和职责混乱。`工程项目名` 固定取 Git 仓库名字，而不是当前工程目录名。

本文是规范文档，不是宣传页。

## 管理文件

- 活动控制文件：`~/.mpc/{工程项目名}/mpc.md`
- 归档控制文件：`~/.mpc/{工程项目名}/mpc_archive.md`
- 锁文件：`~/.mpc/{工程项目名}/.lock.md`

约束如下：

- 这些文件位于按 Git 仓库名字划分的共享目录中，同一仓库的所有会话共享同一份控制文件。
- 文件名固定为 `mpc.md`、`mpc_archive.md` 和 `.lock.md`。
- `.lock.md` 是临时写锁，只读 skill 不创建它。
- 如果文件尚不存在，由 `mpc-master-start` 或首次归档动作创建最小骨架。
- 不要在当前工程目录下寻找或创建本地 `.mpc/`。

## 核心原则

- 主控制器负责拆分任务、查看状态、做回归、做归档，不代替子任务做日常开发。
- 主控侧严格拆分为 4 个 skill：
  - `mpc-master-start`
  - `mpc-master-progress`
  - `mpc-master-regress`
  - `mpc-master-archive`
- 子任务通过显式 `任务标识` 驱动，不再依赖目录或分支自动识别。
- 单目录模式是主流程：多个子任务在同一仓库目录中，通过多开对话并行推进。
- 默认约束是“同一时刻一个任务只由一个对话推进”；本规范不额外提供会话认领机制。
- 子任务默认应可并行；如果存在依赖，必须显式写明 `前序子任务` 和 `后序子任务`。
- 只要涉及同文件、同核心模块、路由或注册表、依赖清单、生成产物、共享导出面，或存在明显顺序关系，就必须拆成串行任务，而不是并行任务。
- `mpc.md` 必须保持固定字段顺序，字段不可省略；空值必须写成 `待填写` 或 `无`。
- 查看类动作必须保持只读，状态推进必须显式触发。
- 所有时间统一使用 `YYYY-MM-DD HH:mm:ss +08:00`。
- 除 `mpc-master-progress` 外，所有写入动作都必须持有 `~/.mpc/{工程项目名}/.lock.md`。

## 子任务状态机

每个子任务只允许使用以下 4 种状态：

- `未开始`
- `进行中`
- `完成`
- `已回归`

唯一允许的正常流转路径为：

`未开始 -> 进行中 -> 完成 -> 已回归`

职责分工如下：

- `mpc-master-start`：创建新任务，初始状态为 `未开始`
- `mpc-slave`：负责 `未开始` 到 `进行中`，以及 `进行中` 到 `完成`
- `mpc-master-progress`：只读查看
- `mpc-master-regress`：负责 `完成` 到 `已回归`
- `mpc-master-archive`：归档已 `已回归` 的任务

归档不是状态，而是只允许发生在回归通过之后的动作。

## `mpc.md` 固定结构

`mpc.md` 中每个任务块都必须保持以下字段顺序：

`任务标识 -> 状态 -> 来源计划文件 -> 执行模式 -> 执行目录 -> 前序子任务 -> 后序子任务 -> 子任务目标 -> 开始时间 -> 完成时间 -> 回归时间 -> 归档时间 -> 最后更新时间 -> 累计耗时 -> 预计剩余时间 -> 当前进度概况 -> 阻塞事项 -> 下一步提示词 -> 开始提示词 -> 完成提示词 -> 完成摘要 -> 回归摘要 -> 归档状态`

补充要求：

- `执行模式` 当前固定为 `single_dir`。
- `执行目录` 当前固定为 `.`。
- `当前进度概况` 最多 5 行。
- `阻塞事项` 最多 5 行；没有阻塞时写 `无`。
- `累计耗时` 与 `预计剩余时间` 使用 `Xd Xh Xm` 形式，例如 `4h 30m`。
- `完成摘要` 至少覆盖：完成内容、涉及文件或模块、自检命令与结果、剩余风险、建议主控回归关注点。
- `回归摘要` 至少覆盖：回归范围、证据、回归结果、是否允许归档。
- `归档状态` 只能是 `未归档` 或 `已归档`。

## `mpc_archive.md`

- 归档文件中的单个任务结构与 `mpc.md` 完全一致。
- `任务总数` 表示当前文件中的任务块数量。
- 归档是移动，不是复制。
- 归档后必须满足：
  - 任务从 `~/.mpc/{工程项目名}/mpc.md` 删除
  - 任务追加到 `~/.mpc/{工程项目名}/mpc_archive.md`
  - `状态` 仍为 `已回归`
  - `归档状态` 变为 `已归档`
  - `归档时间` 已填写
- 查询和依赖检查必须覆盖 `~/.mpc/{工程项目名}/mpc.md` 与 `~/.mpc/{工程项目名}/mpc_archive.md` 的并集，优先查询活动文件。
- 如果同名任务同时存在于两个文件中，视为严重数据异常。

## 并发写入规则

虽然真实冲突概率通常不高，但所有写入仍必须串行化。

1. 除 `mpc-master-progress` 外，所有写入动作都必须先申请 `~/.mpc/{工程项目名}/.lock.md`。
2. 锁文件至少记录：
   - 持有者 skill 名称
   - 目标任务或任务列表
   - 当前仓库目录或分支
   - 加锁时间
3. 如果锁已存在，每 2 秒重试一次，最多等待 60 秒。
4. 如果锁持续超过 10 分钟未释放，视为陈旧锁，必须停止并明确报错。
5. 获取锁后必须重新读取最新 `~/.mpc/{工程项目名}/mpc.md`；必要时也读取 `~/.mpc/{工程项目名}/mpc_archive.md`。
6. 除 `mpc-master-start` 外，每次写事务只允许修改一个任务块和文件头部元信息。
7. `mpc-master-start` 可以在一次事务中追加多个任务块，并以最小改动范围更新直接前序任务的 `后序子任务`。
8. 不得重写无关任务内容、顺序或提示词。
9. 写入必须使用“临时文件 + 原子替换”。
10. 每次成功写入后，都要更新：
    - 文件级 `最后更新时间`
    - 文件级 `任务总数`
    - 任务级 `最后更新时间`
11. 如果待写内容基于旧快照，必须先基于最新内容重建，不能直接覆盖。
12. 只要持有过锁，无论成功还是失败，退出前都必须释放锁。

## 任务拆分规则

`mpc-master-start` 拆分任务时必须满足：

- 任务名全局唯一。
- 不得与 `mpc`、`mpc_archive`、`lock` 等保留名称冲突。
- 任务名只能使用小写字母、数字和下划线。
- 默认把一个需求拆成 3 到 10 个可执行步骤。
- 只有在强原子性要求下才允许超过 10 个步骤。
- 如果任务之间存在明显冲突或强依赖，必须拆成串行子任务，而不是并行任务。
- 只要命中以下任一场景，也应按串行任务建模：同文件、同核心模块、路由或注册表、依赖清单、生成产物、共享导出面。
- 如果是在现有链路后续追加任务，只允许最小范围更新直接前序任务的 `后序子任务`。
- 不新增“路径归属检查”或“会话认领机制”；冲突控制主要依赖任务切分、前后序和调用纪律。

## 各个 skill 的定义

### `mpc-master-start`

手动调用示例：

```text
/mpc-master-start docs/example_plan.md
```

职责：

- 读取需求或计划文档。
- 分析哪些部分可以并行，哪些必须串行。
- 在 `~/.mpc/{工程项目名}/mpc.md` 中创建新的任务块。
- 自动生成：
  - 任务标识
  - 前序和后序关系
  - 子任务目标
  - 开始提示词
  - 完成提示词
- 所有新任务固定写入：
  - `执行模式 = single_dir`
  - `执行目录 = .`
- 必要时创建 `~/.mpc/{工程项目名}/` 和最小 `mpc.md` 骨架。
- 输出首轮可执行任务的建议启动命令，但绝不自动执行。

输出至少包含：

- 新增任务总数
- 首轮可执行任务
- 仅针对首轮可执行任务的建议命令 `/mpc-slave <任务标识>`
- 明确提示每个首轮可执行任务都应在独立对话框中推进

### `mpc-master-progress`

手动调用示例：

```text
/mpc-master-progress
/mpc-master-progress phone_1_requirement_1
```

职责：

- 保持只读。
- 展示全部活动任务概览，或展示单个任务详情。
- 优先查询 `~/.mpc/{工程项目名}/mpc.md`，未命中时再查 `~/.mpc/{工程项目名}/mpc_archive.md`。

按状态展示规则：

- 单任务查询时，无论当前状态如何，都优先显示 `子任务目标`
- `未开始`：显示 `开始提示词`
- `进行中`：显示耗时、进度概况、阻塞事项、预计剩余时间、下一步提示词
- `完成`：显示完成时间、累计耗时、完成摘要、完成提示词
- `已回归`：显示开始时间、完成时间、回归时间、累计耗时、回归摘要、归档状态

### `mpc-master-regress`

手动调用示例：

```text
/mpc-master-regress phone_1_requirement_1
```

职责：

- 只处理一个当前状态为 `完成` 的任务。
- 回归证据优先来自：
  - `完成摘要`
  - 自检命令与结果
  - 当前总代码状态
  - `子任务目标`
- 不再假设一定能拿到该任务独立的 Git diff。
- 先给出建议，再等待明确确认。
- 只有得到明确确认后，才把任务推进到 `已回归`。

如果 `完成摘要` 缺少“涉及文件或模块”或“自检命令与结果”，且调用者也没有提供额外证据，应优先给出“证据不足”或“建议回归不通过”的结论。

### `mpc-master-archive`

手动调用示例：

```text
/mpc-master-archive phone_1_requirement_1
```

职责：

- 只处理一个当前状态为 `已回归` 的任务。
- 把该任务从 `~/.mpc/{工程项目名}/mpc.md` 移动到 `~/.mpc/{工程项目名}/mpc_archive.md`。
- 必要时创建最小归档文件。

### `mpc-slave`

手动调用示例：

```text
/mpc-slave phone_1_requirement_1
```

职责：

- 必须接收一个显式 `任务标识` 参数。
- 禁止从当前目录名、git 分支名或最近改动中自动猜测任务。
- 使用 `~/.mpc/{工程项目名}/mpc.md` 作为控制文件。
- 只负责 `未开始` 到 `进行中` 到 `完成`。

按状态行为：

- `未开始`
  - 检查所有前序任务，查询范围覆盖活动区和归档区
  - 只有全部前序任务都为 `已回归` 时才允许启动
  - 初始化开始时间、预计剩余时间和下一步提示词
- `进行中`
  - 更新进度概况、阻塞事项、预计剩余时间、下一步提示词、最后更新时间
  - 优先读取当前仓库目录 `./planning/` 下最新且最相关的文件
  - 如果证据足够，先提出“建议已完成”
  - 证据展示必须至少包含：已完成内容、涉及文件或模块、自检命令与结果、尚存风险、建议主控回归关注点
  - 只有得到明确确认后，才推进到 `完成`
- `完成`
  - 只展示完成信息
  - 不能直接推进到 `已回归`
- `已回归`
  - 只展示回归和归档信息
  - 提示调用者改用 `mpc-master-archive`

## 最小闭环要求

以下能力都成立时，这套设计才算真正可用：

1. `mpc-master-start` 能稳定创建结构正确的子任务。
2. `mpc-master-progress` 能稳定提供只读总览与任务树。
3. `mpc-slave` 能根据显式 `任务标识` 准确命中自己的任务，并在确认后推进到 `完成`。
4. `mpc-master-regress` 能基于完成摘要、自检结果和当前总代码状态给出结论，并在确认后推进到 `已回归`。
5. `mpc-master-archive` 能安全归档一个已回归任务。
6. 多个对话并行工作时，不会因为覆盖写导致状态丢失。

## 明确禁止的行为

- 不得把“查看状态”设计成“顺便改状态”。
- 不得让 `mpc-slave` 绕过前序依赖。
- 不得让 `mpc-slave` 从 `进行中` 直接跳到 `已回归`。
- 不得让 `mpc-master-progress` 承担回归或归档动作。
- 不得归档尚未完成回归的任务。
- 不得在未持有 `~/.mpc/{工程项目名}/.lock.md` 时写控制文件。
- 不得只查 `~/.mpc/{工程项目名}/mpc.md` 就判断前序任务不存在。
- 不得在更新一个任务时重写无关任务块。
- 不得省略固定字段，导致下游解析失败。
- 不得让 `mpc-slave` 无参数运行或自动猜测任务名。
