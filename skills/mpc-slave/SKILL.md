# MPC Slave

## 概览

在当前项目仓库内工作。必须接收一个显式任务名称参数；不要从当前目录名、当前 git 分支名或最近改动自动识别任务。先解析当前项目的 Git 仓库根目录，再把 `<repo-root>/.mpc/mpc.md` 作为目标控制文件；不要随着触发位置漂移到子目录下的其他 `.mpc/`。只负责 `未开始 -> 进行中 -> 完成` 的推进；不要承担回归或归档职责。

这个 skill 的重点是推进已记录任务的执行状态与进度同步，并在展示给执行者的提示词中持续保留 GSD 能力前缀。

## 任务识别

按以下顺序识别当前任务：

1. 读取调用参数中的 `任务标识`。
2. 在 `<repo-root>/.mpc/mpc.md` 中查找同名 `任务标识`。
3. 要求该任务存在且未被归档。

如果没有传入任务名，或 `<repo-root>/.mpc/mpc.md` 中不存在该任务，立即报错并停止。不要猜测、不要模糊匹配、不要改用归档文件中的任务作为当前目标。

## 通用写入约束

- 每次准备写入 `<repo-root>/.mpc/mpc.md` 前先持有 `<repo-root>/.mpc/.lock.md`。
- 锁存在时每 2 秒重试一次，最多等待 60 秒；锁超过 10 分钟视为陈旧锁并停止。
- 锁文件至少记录：`mpc-slave`、目标任务、当前仓库目录或分支、加锁时间。
- 获取锁后重新读取最新 `<repo-root>/.mpc/mpc.md`；检查目标任务状态是否仍与当前判断一致。
- 只修改当前任务块与文件头部 `元信息`。
- 使用“临时文件 + 原子替换”写回。
- 无论成功或失败，都释放锁。

## 固定字段顺序

按以下顺序精确读取和更新任务块：

`任务标识 -> 状态 -> 来源计划文件 -> 执行模式 -> 执行目录 -> 前序子任务 -> 后序子任务 -> 子任务目标 -> 开始时间 -> 完成时间 -> 回归时间 -> 归档时间 -> 最后更新时间 -> 累计耗时 -> 预计剩余时间 -> 当前进度概况 -> 阻塞事项 -> 下一步提示词 -> 开始提示词 -> 完成提示词 -> 完成摘要 -> 回归摘要 -> 归档状态`

## 当状态为 `未开始`

1. 读取全部 `前序子任务`。
2. 依赖检查范围必须覆盖 `<repo-root>/.mpc/mpc.md` 与 `<repo-root>/.mpc/mpc_archive.md` 的并集。
3. 只有当前序子任务全部为 `已回归` 时，才允许启动。
4. 为 `预计剩余时间` 形成一个初始估算值，格式必须是 `Xd Xh Xm`；若调用者未给出估算，先给出保守估算并明确说明。
5. 原子更新：
   - `状态 = 进行中`
   - `开始时间 = 当前时间`
   - `最后更新时间 = 当前时间`
   - `预计剩余时间 = 初始估算值`
   - `下一步提示词 = 开始提示词`
6. 写回后，按 `开始提示词` 继续推进当前任务。

如果任一前序任务在活动区与归档区都找不到，立即报错并停止。

## 当状态为 `进行中`

每次运行都要更新进度。信息来源优先级固定为：

1. 当前仓库目录下 `./planning/` 中与本任务最相关的最新文件。
2. 当前仓库目录的实际代码改动与当前会话上下文。

更新时至少处理：

- `当前进度概况`，最多 5 行。
- `阻塞事项`，没有阻塞写 `无`。
- `预计剩余时间`
- `下一步提示词`
- `最后更新时间`

更新 `下一步提示词` 时遵守这些规则：

- 必须保留 `利用gsd skills的能力，实现需求：<当前子任务目标摘要>` 这一前缀。
- 推荐模板：

```text
利用gsd skills的能力，实现需求：<需求摘要>。结合当前已完成内容、剩余工作与阻塞项继续推进下一步，并准备同步最新进度。
```

- 不要把它改写成不含 GSD 能力语义的普通备注。

如果 `当前进度概况`、`阻塞事项`、`下一步提示词` 均无实质变化，允许只更新时间。

## 建议完成与完成写回

其中，`子任务目标` 是判断当前任务是否可以进入“建议已完成”的主标准。

如果基于 `子任务目标`、当前产出与自检结果形成“建议已完成”结论：

1. 先整理完成证据。
2. 先向调用者展示：
   - 已完成内容
   - 涉及文件或模块
   - 自检命令与结果
   - 尚存风险
   - 建议主控回归关注点
   - 一棵完整的完成决策任务树
3. 只有在调用者明确认可“建议已完成”后，才原子更新：
   - `状态 = 完成`
   - `完成时间 = 当前时间`
   - `累计耗时`
   - `完成摘要`
   - `最后更新时间 = 当前时间`

`完成摘要` 必须至少覆盖：

- 已完成内容
- 涉及文件或模块
- 自检命令与结果
- 尚存风险
- 建议主控回归关注点

如果调用者认为证据不足或仍有未闭合事项，保持 `状态 = 进行中` 并继续更新进度字段。

## 当状态为 `完成`

只展示：

- `完成时间`
- `累计耗时`
- `完成摘要`
- `完成提示词`

不要把任务改成 `已回归`。

## 当状态为 `已回归`

只展示：

- `回归时间`
- `回归摘要`
- `归档状态`

并明确提示该任务只能由 `mpc-master-archive <任务名>` 归档。

## 禁止事项

- 不要允许无参数运行。
- 不要让手工指定之外的上下文覆盖当前目标任务。
- 不要绕过前序依赖直接把 `未开始` 改成 `进行中`。
- 不要把 `进行中` 直接改成 `已回归`。
- 不要只查 `<repo-root>/.mpc/mpc.md` 就判定前序任务不存在。
