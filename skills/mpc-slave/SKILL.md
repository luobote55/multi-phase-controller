# MPC Slave

## 概览

在当前子任务 worktree 内工作。不要接收额外的任务名称参数；总是从当前目录名与当前 git 分支名识别任务，并把 `~/.mpc/{工程项目名}/mpc.md` 作为目标控制文件。`工程项目名` 固定取 Git 仓库名字，而不是当前 worktree 目录名；不要在当前 worktree 下寻找 `.mpc/`。只负责 `未开始 -> 进行中 -> 完成` 的推进；不要承担回归或归档职责。

## 任务识别

按以下顺序识别当前任务：

1. 获取当前 git 分支名。
2. 获取当前 worktree 目录名。
3. 要求二者完全一致。
4. 在 `~/.mpc/{工程项目名}/mpc.md` 中查找同名 `任务标识`。

如果目录名与分支名不一致，或 `~/.mpc/{工程项目名}/mpc.md` 中不存在该任务，立即报错并停止。不要猜测、不要模糊匹配、不要改用归档文件中的任务作为当前目标。

## 通用写入约束

- 每次准备写入 `~/.mpc/{工程项目名}/mpc.md` 前先持有 `~/.mpc/{工程项目名}/.lock.md`。
- 锁存在时每 2 秒重试一次，最多等待 60 秒；锁超过 10 分钟视为陈旧锁并停止。
- 锁文件至少记录：`mpc-slave`、目标任务、当前 worktree/分支、加锁时间。
- 获取锁后重新读取最新 `~/.mpc/{工程项目名}/mpc.md`；检查目标任务状态是否仍与当前判断一致。
- 只修改当前任务块与文件头部 `元信息`。
- 使用“临时文件 + 原子替换”写回。
- 无论成功或失败，都释放锁。

## 固定字段顺序

按以下顺序精确读取和更新任务块：

`任务标识 -> 状态 -> 来源计划文件 -> worktree名称 -> worktree目录 -> worktree分支 -> 前序子任务 -> 后序子任务 -> 子任务目标 -> 开始时间 -> 完成时间 -> 回归时间 -> 归档时间 -> 最后更新时间 -> 累计耗时 -> 预计剩余时间 -> 当前进度概况 -> 阻塞事项 -> 下一步提示词 -> 开始提示词 -> 完成提示词 -> 完成摘要 -> 回归摘要 -> 归档状态`

## 当状态为 `未开始`

1. 读取全部 `前序子任务`。
2. 依赖检查范围必须覆盖 `~/.mpc/{工程项目名}/mpc.md` 与 `~/.mpc/{工程项目名}/mpc_archive.md` 的并集。
3. 只有当前序子任务全部为 `已回归` 时，才允许启动。
4. 为 `预计剩余时间` 形成一个初始估算值，格式必须是 `Xd Xh Xm`；若调用者未给出估算，先给出保守估算并明确说明。
5. 原子更新：
   - `状态 = 进行中`
   - `开始时间 = 当前时间`
   - `最后更新时间 = 当前时间`
   - `预计剩余时间 = 初始估算值`
   - `下一步提示词 = 开始提示词`
6. 写回后，按 `开始提示词` 继续推进当前任务。

如果任一前序任务在活动区与归档区都找不到，立即报错并停止。

## 当状态为 `进行中`

每次运行都要更新进度。信息来源优先级固定为：

1. 当前 worktree 下 `./planning/` 中与本任务最相关的最新文件。
2. 当前 worktree 的实际代码改动与当前会话上下文。

选择 `./planning/` 文件时遵守：

- 优先文件名包含 `任务标识` 的文件。
- 有多个候选时，按修改时间从新到旧取最近一份。
- 若修改时间相同，取文件名字典序最后一份。

更新时至少处理：

- `当前进度概况`，最多 5 行。
- `阻塞事项`，没有阻塞写 `无`。
- `预计剩余时间`
- `下一步提示词`
- `最后更新时间`

如果 `当前进度概况`、`阻塞事项`、`下一步提示词` 均无实质变化，允许只更新时间。

## 建议完成与完成写回

其中，`子任务目标` 是判断当前任务是否可以进入“建议已完成”的主标准。

如果基于 `子任务目标`、当前产出与自检结果形成“建议已完成”结论：

1. 先整理完成证据。
2. 先向调用者展示：
   - 已完成内容
   - 尚存风险
   - 自检结果
   - 建议主控回归关注点
   - 一棵完整的完成决策任务树
3. 完成决策任务树必须遵守：
   - 基础结构仍使用完整任务树。
   - 仅当前任务的直接 `后序子任务` 允许追加后续决策标记，不扩散到其他层级。
   - 直接后序任务追加 `[决策]` 的条件是：该任务当前为 `未开始`，且除当前任务外，其余 `前序子任务` 都已在活动区或归档区满足 `状态 = 已回归`；已归档任务同样视为满足。
   - `[推荐]` 只允许追加给一个直接候选，默认取 `后序子任务` 列表中第一个满足 `[决策]` 条件的任务。
   - 节点展示格式固定为 `task_name [未开始] [决策][推荐]` 或 `task_name [未开始] [决策]`。
   - 如果没有任何满足条件的直接候选，仍输出完整任务树，但不追加 `[推荐]`。
4. 只有在调用者明确认可“建议已完成”后，才原子更新：
   - `状态 = 完成`
   - `完成时间 = 当前时间`
   - `累计耗时`
   - `完成摘要`
   - `最后更新时间 = 当前时间`

`完成摘要` 必须至少覆盖：

- 已完成内容
- 尚存风险
- 自检结果
- 建议主控回归关注点

如果调用者认为证据不足或仍有未闭合事项，保持 `状态 = 进行中` 并继续更新进度字段。

## 当状态为 `完成`

只展示：

- `完成时间`
- `累计耗时`
- `完成摘要`
- `完成提示词`

不要把任务改成 `已回归`。

## 当状态为 `已回归`

只展示：

- `回归时间`
- `回归摘要`
- `归档状态`

并明确提示该任务只能由 `mpc-master-archive <任务名>` 归档。

## 禁止事项

- 不要接收手工指定的任务名来覆盖当前 worktree 识别结果。
- 不要绕过前序依赖直接把 `未开始` 改成 `进行中`。
- 不要把 `进行中` 直接改成 `已回归`。
- 不要只查 `~/.mpc/{工程项目名}/mpc.md` 就判定前序任务不存在。
