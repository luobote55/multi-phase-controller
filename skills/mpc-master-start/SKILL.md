# MPC Master Start

## 概览

读取一个需求计划文件，拆分出可执行的 MPC 子任务，并把结果写入 `~/.mpc/{工程项目名}/mpc.md`。控制文件目录固定使用共享路径 `~/.mpc/{工程项目名}/`，其中 `工程项目名` 固定取 Git 仓库名字；不要在当前 worktree 下寻找 `.mpc/`。只负责初始化控制文件、生成任务块、维护依赖关系和输出 worktree 建议命令；不要代替子任务执行开发，也不要自动执行任何 git worktree 命令。

## 不可违背的约束

- 只把调用者提供的计划文件，以及现有 `~/.mpc/{工程项目名}/mpc.md` / `~/.mpc/{工程项目名}/mpc_archive.md` 当作事实来源。
- 在任何写入开始前先申请 `~/.mpc/{工程项目名}/.lock.md`；锁存在时每 2 秒重试一次，最多等待 60 秒；锁超过 10 分钟未释放时停止并报告陈旧锁。
- 在锁文件中至少写入：当前 skill 名称、目标任务列表、当前 worktree/分支、加锁时间。
- 获取锁后重新读取最新的 `~/.mpc/{工程项目名}/mpc.md`；必要时同时读取 `~/.mpc/{工程项目名}/mpc_archive.md`。
- 写入时只允许：
  - 追加新的子任务块。
  - 以最小改动范围更新直接前序任务的 `后序子任务`。
  - 更新文件头部 `最后更新时间` 与 `任务总数`。
- 不得重排、折叠、润色或重写无关任务块。
- 所有时间统一写成 `YYYY-MM-DD HH:mm:ss +08:00`。
- 所有空值字段必须保留并写成 `待填写` 或 `无`，不得省略字段。
- 使用“临时文件 + 原子替换”写回，不要原地覆盖。
- 无论成功或失败，只要持有过锁，都必须在结束前释放 `~/.mpc/{工程项目名}/.lock.md`。

## 固定结构

始终按以下顺序创建每个任务块：

`任务标识 -> 状态 -> 来源计划文件 -> worktree名称 -> worktree目录 -> worktree分支 -> 前序子任务 -> 后序子任务 -> 开始时间 -> 完成时间 -> 回归时间 -> 归档时间 -> 最后更新时间 -> 累计耗时 -> 预计剩余时间 -> 当前进度概况 -> 阻塞事项 -> 下一步提示词 -> 开始提示词 -> 完成提示词 -> 完成摘要 -> 回归摘要 -> 归档状态`

其中必须满足：

- `状态` 初始固定为 `未开始`。
- `worktree名称`、`worktree目录名`、`worktree分支名` 与 `任务标识` 完全一致。
- `worktree目录` 固定写成 `../<任务标识>`。
- `归档状态` 初始固定为 `未归档`。
- `阻塞事项` 初始写 `无`。
- 其他未确定字段写 `待填写`。

## 拆分流程

1. 读取调用者提供的计划文件。
2. 判断哪些工作可以并行，哪些必须串行。
3. 为每个子任务生成全局唯一的任务名。
4. 仅使用小写字母、数字、下划线命名任务；拒绝与 `mpc`、`mpc_archive`、`lock` 等保留名称冲突的名字。
5. 在新增前校验 `~/.mpc/{工程项目名}/mpc.md` 与 `~/.mpc/{工程项目名}/mpc_archive.md` 中都不存在同名任务。
6. 默认把单个需求拆成 3 到 10 个可执行步骤；只有强原子性要求下才允许更多。
7. 如果任务之间存在明显代码冲突、强顺序依赖或共享同一核心改动点，拆成串行子任务，并显式写明 `前序子任务` / `后序子任务`。
8. 如果是向现有链路追加后续任务，只允许最小范围修改直接前序任务的 `后序子任务` 字段。

## 生成内容

为每个新任务自动生成：

- `任务标识`
- `前序子任务`
- `后序子任务`
- `开始提示词`
- `完成提示词`

生成提示词时遵守这些规则：

- `开始提示词` 用于指导子任务在自己的 worktree 内启动工作，先聚焦边界确认、上下文装载、任务执行。
- `完成提示词` 用于指导主控后续做回归确认，并明确要求给出是否允许归档的结论。
- 不要把回归或归档职责提前塞给子任务。

## 文件初始化

- 如果 `~/.mpc/{工程项目名}/` 不存在，先创建共享控制目录。
- 如果 `~/.mpc/{工程项目名}/mpc.md` 不存在，创建骨架文件并写入 `# MPC 控制文件`、`## 元信息`、`版本`、`最后更新时间`、`任务总数`。
- 不要在本 skill 中自动创建 worktree。
- 不要在本 skill 中主动创建 `~/.mpc/{工程项目名}/mpc_archive.md`，除非实现上必须依赖它做重名检查且文件尚不存在；此时只创建最小骨架。

## 任务树输出

- 写入完成后，按 `~/.mpc/{工程项目名}/mpc.md` 与 `~/.mpc/{工程项目名}/mpc_archive.md` 的并集生成最新任务树；如果归档文件不存在，可以忽略。
- `前序子任务` 与 `后序子任务` 在存在多个任务时，统一按 `、` 拆分；`前序子任务 = 无` 的任务视为根节点。
- 子节点顺序严格使用父任务 `后序子任务` 中的顺序；根节点顺序优先保持 `mpc.md` 中的原始顺序。
- 树状图字符统一使用 `├─`、`└─`、`│  ` 与 3 个空格缩进。
- 如果发现同名任务同时存在于活动区与归档区、循环依赖、缺失子任务、或同一子任务被多个父任务直接声明为后序任务，立即报告数据异常并停止。
- 本 skill 默认可以只输出任务名；如果当前控制器中已经存在混合状态任务，也允许在节点后追加状态标签。

## 输出要求

执行完成后，向调用者输出：

- 先输出最新任务树。
- 本次新增子任务总数。
- 首轮可执行子任务，也就是 `前序子任务 = 无`，或其前序子任务已经在现有控制文件中处于 `已回归` 的新任务。
- 仅为首轮可执行子任务输出建议执行的 worktree 创建命令。
- 被前序子任务阻塞的新任务也必须出现在任务树中，但不要再额外用平铺列表逐条打印；它们只写入 `~/.mpc/{工程项目名}/mpc.md`，等待后续由 `mpc-master-progress` / `mpc-slave` 驱动。
- 如果本次新增任务里没有任何首轮可执行项，明确输出“首轮可执行子任务：无”，并简要指出阻塞来自哪些前序任务即可，不要展开打印全部阻塞链路。

命令只作为建议输出，格式使用：

```bash
git worktree add ../<子任务名称> -b <子任务名称> <基线分支>
```

默认把 `<基线分支>` 设为当前主工作区分支；如果计划文件明确指定基线分支，则以计划文件为准。

## 禁止事项

- 不要自动执行 `git worktree add`。
- 不要修改已有任务的业务提示词，除非该任务是本次新增链路的直接前序任务，且只更新它的 `后序子任务`。
- 不要把“任务拆分”实现成对整个 `mpc.md` 的重写。
