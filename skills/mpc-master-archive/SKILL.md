# MPC Master Archive

## 概览

把单个 `已回归` 状态的子任务从活动控制文件移动到归档控制文件。这里的“归档”是移动，不是复制；活动区删除、归档区追加，两边元信息都要同步更新。

## 不可违背的约束

- 只处理一个明确指定的 `任务标识`。
- 写入前先持有 `.mpc/mpc.lock`，并在结束时释放。
- 获取锁后重新读取最新 `.mpc/mpc.md`；必要时同时读取 `.mpc/mpc-archive.md`。
- 目标任务必须存在于 `.mpc/mpc.md` 中，且状态为 `已回归`。
- 如果同名任务已经存在于 `.mpc/mpc-archive.md`，视为数据异常并停止。
- 使用“临时文件 + 原子替换”写回两个文件。
- 不要修改无关任务块。

## 归档流程

1. 读取并校验目标任务。
2. 如果 `.mpc/mpc-archive.md` 不存在，创建最小骨架文件。
3. 将目标任务块从 `.mpc/mpc.md` 移动到 `.mpc/mpc-archive.md` 末尾。
4. 在被移动的任务块中写入：
   - `归档状态 = 已归档`
   - `归档时间 = 当前时间`
   - `最后更新时间 = 当前时间`
5. 从 `.mpc/mpc.md` 删除该任务块。
6. 同步更新两个文件头部：
   - `最后更新时间`
   - `任务总数`

## 一致性要求

- 被归档任务保留原有字段顺序与内容，只更新归档相关字段。
- 即使其他未归档任务仍把它当作 `前序子任务`，也允许归档；后续解析必须能从 `.mpc/mpc-archive.md` 命中它。
- 活动文件和归档文件中的 `任务总数` 必须分别反映各自当前块数。

## 解析要求

始终按以下顺序保留任务块结构：

`任务标识 -> 状态 -> 来源计划文件 -> worktree名称 -> worktree目录 -> worktree分支 -> 前序子任务 -> 后序子任务 -> 开始时间 -> 完成时间 -> 回归时间 -> 归档时间 -> 最后更新时间 -> 累计耗时 -> 预计剩余时间 -> 当前进度概况 -> 阻塞事项 -> 下一步提示词 -> 开始提示词 -> 完成提示词 -> 完成摘要 -> 回归摘要 -> 归档状态`

归档完成后必须满足：

- `状态 = 已回归`
- `归档状态 = 已归档`
- `归档时间` 已填写

## 输出要求

向调用者明确说明：

- 归档是否成功
- 任务已从哪个文件移动到哪个文件
- 两个控制文件更新后的任务总数

## 禁止事项

- 不要归档 `未开始`、`进行中` 或 `完成` 的任务。
- 不要把归档实现成复制。
- 不要重写整个活动任务列表的顺序。
