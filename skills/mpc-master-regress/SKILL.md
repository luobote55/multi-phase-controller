# MPC Master Regress

## 概览

对单个 `完成` 状态的子任务执行主控回归。先收集并展示回归证据，先给出建议，再等待调用者确认；只有在调用者明确确认通过后，才把任务从 `完成` 更新为 `已回归`。

## 不可违背的约束

- 只处理一个明确指定的 `任务标识`。
- 该任务必须存在于 `.mpc/mpc.md` 中，且当前状态必须仍为 `完成`。
- 写入前先持有 `.mpc/mpc.lock`，写后或失败后都释放锁。
- 获取锁后重新读取最新 `.mpc/mpc.md`，确认状态没有被其他会话改动。
- 使用“临时文件 + 原子替换”写回。
- 只允许修改目标任务块和文件头部 `元信息`。
- 不要修改 `.mpc/mpc-archive.md`。

## 回归流程

1. 读取最新 `.mpc/mpc.md`。
2. 校验目标任务存在且状态为 `完成`。
3. 读取该任务的：
   - `完成提示词`
   - `完成摘要`
   - `开始时间`
   - `完成时间`
   - `累计耗时`
4. 结合当前仓库中的实际代码改动、自检结果、剩余风险与任务业务目标形成回归证据。
5. 先向调用者输出：
   - 回归范围
   - 使用的证据
   - 回归结论建议：`建议回归通过` 或 `建议回归不通过`
   - 是否允许归档的建议
6. 只有在调用者明确确认“回归通过”后，才写回状态。

## 写回规则

当调用者确认通过时，原子更新：

- `状态 = 已回归`
- `回归时间 = 当前时间`
- `回归摘要 = 精炼回归结论`
- `最后更新时间 = 当前时间`

同步更新文件头部：

- `最后更新时间`
- `任务总数`

`回归摘要` 至少覆盖：

- 回归范围
- 依据证据
- 回归结果
- 是否允许归档

## 不通过时的处理

如果回归动作失败，或调用者认为证据不足：

- 保持 `状态 = 完成`
- 不得提前改成 `已回归`
- 清楚说明失败原因、缺失证据或待补事项

## 解析要求

按固定字段标题精确读取和更新，不要丢字段，不要改顺序。任务块字段顺序固定为：

`任务标识 -> 状态 -> 来源计划文件 -> worktree名称 -> worktree目录 -> worktree分支 -> 前序子任务 -> 后序子任务 -> 开始时间 -> 完成时间 -> 回归时间 -> 归档时间 -> 最后更新时间 -> 累计耗时 -> 预计剩余时间 -> 当前进度概况 -> 阻塞事项 -> 下一步提示词 -> 开始提示词 -> 完成提示词 -> 完成摘要 -> 回归摘要 -> 归档状态`

## 禁止事项

- 不要把“建议回归通过”直接等同于“已经回归通过”。
- 不要为方便归档而跳过回归证据收集。
- 不要改写其他任务块。
