# MPC Master Regress

## 概览

对单个 `完成` 状态的子任务执行可选的主控回归确认。目标控制文件固定为 `<repo-root>/.mpc/mpc.md`；所有控制文件都放在当前项目的 Git 仓库根目录 `.mpc/` 下，即使从子目录触发也要先解析到仓库根目录。先收集并展示回归证据，先给出建议，再等待调用者确认；只有在调用者明确确认通过后，才把任务从 `完成` 更新为 `已回归`。

这里的回归对象，应理解为“基于利用 GSD skills 推进后的任务产出”。

## 不可违背的约束

- 只处理一个明确指定的 `任务标识`。
- 该任务必须存在于 `<repo-root>/.mpc/mpc.md` 中，且当前状态必须仍为 `完成`。
- 写入前先持有 `<repo-root>/.mpc/.lock.md`，写后或失败后都释放锁。
- 获取锁后重新读取最新 `<repo-root>/.mpc/mpc.md`，确认状态没有被其他会话改动。
- 使用“临时文件 + 原子替换”写回。
- 只允许修改目标任务块和文件头部 `元信息`。
- 不要修改 `<repo-root>/.mpc/mpc_archive.md`。

## 回归流程

1. 读取最新 `<repo-root>/.mpc/mpc.md`。
2. 校验目标任务存在且状态为 `完成`。
3. 读取该任务的：
   - `子任务目标`
   - `完成提示词`
   - `完成摘要`
   - `开始时间`
   - `完成时间`
   - `累计耗时`
4. 结合以下来源形成回归证据：
   - `完成摘要`
   - 自检命令与结果
   - 当前仓库中的总代码状态
   - 剩余风险
   - `子任务目标`
5. 不再假设一定能拿到该任务独立的 Git diff。
6. 先向调用者输出：
   - 回归范围
   - 使用的证据
   - 回归结论建议：`建议回归通过` 或 `建议回归不通过`
   - 是否允许归档的建议
   - 当前最新完整任务树
7. 只有在调用者明确确认“回归通过”后，才写回状态。

## 证据不足时的默认结论

如果 `完成摘要` 没有覆盖以下内容，且调用者也没有补充同等证据：

- 涉及文件或模块
- 自检命令与结果

则默认优先输出“证据不足”或“建议回归不通过”，而不是勉强通过。

## 写回规则

当调用者确认通过时，原子更新：

- `状态 = 已回归`
- `回归时间 = 当前时间`
- `回归摘要 = 精炼回归结论`
- `最后更新时间 = 当前时间`

同步更新文件头部：

- `最后更新时间`
- `任务总数`

`回归摘要` 至少覆盖：

- 回归范围
- 依据证据
- 回归结果
- 是否允许归档

## 任务树输出

- 在首次给出回归建议时，附带输出一次当前最新任务树。
- 如果调用者确认通过并成功写回状态，再输出一次写回后的最新任务树。
- 如果调用者未确认通过，或本轮因证据不足未写回状态，仍输出未变更的当前任务树。
- 任务树基于 `<repo-root>/.mpc/mpc.md` 与 `<repo-root>/.mpc/mpc_archive.md` 的并集生成；如果归档文件不存在，可以忽略。
- `前序子任务` 与 `后序子任务` 在存在多个任务时，统一按 `、` 拆分；`前序子任务 = 无` 的任务视为根节点。
- 子节点顺序严格使用父任务 `后序子任务` 中的顺序；根节点顺序优先保持 `mpc.md` 中的原始顺序。
- 树状图字符统一使用 `├─`、`└─`、`│  ` 与 3 个空格缩进。
- 节点后默认追加状态标签，如 `task_name [已回归]`；已归档任务统一显示为 `task_name [已归档]`。
- 如果发现同名任务同时存在于活动区与归档区、循环依赖、缺失子任务、或同一子任务被多个父任务直接声明为后序任务，立即报告数据异常并停止。

## 禁止事项

- 不要把“建议回归通过”直接等同于“已经回归通过”。
- 不要为方便归档而跳过回归证据收集。
- 不要改写其他任务块。
